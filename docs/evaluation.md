# 评估协议与当前局限

目前完成的是框架抽取与工程验证。离线例子采用固定事实回放，不代表真实物理过程；pytest 数量不等于机器人实验次数。

## 应记录什么

每次执行保存原计划、组件名称、执行参数、context 回执、观测元数据、判定证据、重规划事件和结果。外部评估还应记录模型/权重版本、任务配置摘要、随机种子、场景划分与人工结果标注。
`inspect` 输出批次数、检查次数、完成步数、重规划次数与时长；`physical_success` 始终为空，必须由独立评价器补充，不能用执行器自己的成功判定充当真值。

## 泛化评估

1. 先测底层单步能力，再测相同技能组成的长任务。
2. 留出未参与调试的顺序、任务长度、布局和表达；在测试集上不改规则或阈值。
3. 跨任务类型验证完成与交接，不只改变颜色。
4. 若声称跨模型通用，必须接入第二种真实动作模型，而非仅添加接口或回放。
5. 进行多次独立实验，报告试验数、完整任务成功率和区间，以及过早/过晚切换、恢复、人类介入和延迟。

## 对照实验

完整提示词；拆分加固定时长；仅执行事件；仅视觉证据；事件与视觉结合；具有理想切换时机的诊断上限。与 RPent 等方法比较时保持底层权重、观测与计算预算可比。

## 尚未实现或证明

- 任意槽位访问、自动获得底层模型未训练的新技能。
- 图片和示范视频输入理解；现在只有媒体引用契约。
- 经跨任务验证的完成检测算法、校准置信度、自动学习技能能力边界。
- 多机器人并行、任务重启后自动恢复、完整计划 KV 预加载。
- 真机稳定性、跨模型性能或论文新颖性。

目前 `max_replans=0` 的默认配置异常即停止。启用重规划是可测试的扩展能力，不能视为经过真机验证的自动恢复策略。
